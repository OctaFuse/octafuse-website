AI 能力正在从文本模型扩展到图片生成、Agent Tools、私有模型与更多专用服务。供应商、兼容端点、Coding Plan、自托管服务和团队内部账号，各有自己的 **Base URL**、密钥、额度、价格与日志；应用真正需要的是一个稳定入口、一套可控路由、清楚的预算和可追溯的调用记录。

**OctaFuse 是可自托管的 AI 能力网关与运营控制面。** 你可以统一接入官方 Provider、第三方兼容端点、图片生成与编辑、语音转写、Agent Tools 和私有模型服务，并通过 Request Surface → Route Pool → Upstream Target 管理路由、故障转移、Provider 熔断、预算、计费、审计和管理 API。对客户端而言，仍然是一个 Gateway URL 和一把用户 Key。

## 应用场景

<CardGrid stagger>
	<Card title="个人开发者与工具链" icon="add-document">
		把模型订阅、Coding Plan、图片生成、Agent Tools 与备用上游汇总成一个 Gateway。Cursor、CLI、脚本或自研工具只需要配置一个 Gateway URL 和一把用户 Key。
	</Card>
	<Card title="AI 应用与 Agent 团队" icon="laptop">
		业务代码面向稳定模型 ID 和统一协议开发。模型切换、灰度路线、备用 Provider、失败降级和默认参数都放在网关层调整。
	</Card>
	<Card title="团队平台与 IT 管理" icon="setting">
		为部门、项目、成员或客户分别创建用户与 API Key，配置预算周期、状态和 metadata，让模型调用治理从业务服务里独立出来。
	</Card>
	<Card title="API 代理与分销服务" icon="external">
		接入多个上游 Provider；同一供应商有多个账号时创建多个 Provider。对下游客户发独立 Key，并通过请求日志、成本口径和审计记录做分客户管理。
	</Card>
	<Card title="私有与混合模型入口" icon="setting">
		把自托管兼容服务、内部模型、Ollama / vLLM 旁路和公网模型放在同一套路由体系后面，对外暴露一致的访问方式。
	</Card>
	<Card title="成本与稳定性运营" icon="analytics">
		通过模型、Provider、用户和可靠性维度观察用量与失败情况，再调整 Route Pool 策略、priority / weight、预算方案与按时段调价。
	</Card>
</CardGrid>

## 功能特性

<CardGrid stagger>
	<Card title="多协议与多模态统一入口" icon="external">
		支持 OpenAI Chat、Images、Audio Transcriptions 与 Models，Anthropic Messages，以及 Gemini `generateContent` / `streamGenerateContent`；门户可用公开 `GET /catalog/models` 发现能力。
	</Card>
	<Card title="图片生成 / 编辑" icon="open-book">
		OpenAI 兼容 `POST /v1/images/generations` 与 `edits`；目录价支持 token 分项与按张（`per_image`）。Playground / Simulator 可联调出图与计费日志。
	</Card>
	<Card title="Agent Tools" icon="puzzle">
		面向 Agent 的可扩展产品 API（`/v1/tools/*`）。Web Search 支持博查、Tavily、CleverSee、腾讯云 WSA；Web Fetch 支持 Firecrawl、Tavily Extract、Jina Reader；Deep Search 支持 Firecrawl Search、Jina Search。
	</Card>
	<Card title="Surface → Pool → Target 路由" icon="random">
		客户端请求先按协议与 operation 命中 Request Surface，再进入 Route Pool；Pool 内按 priority 分层，同层根据策略与 weight 排序 Upstream Target，失败后自动切换。
	</Card>
	<Card title="预置 Provider 与 Models" icon="document">
		Admin 可一键导入大量供应商 / 模型预设：除官方模型厂外，还覆盖聚合平台与各类 Coding / Token Plan，预填 Base URL 与模型目录价等信息，无需到处查找再手工维护。
	</Card>
	<Card title="单 Key Provider 与预置导入" icon="approve-check">
		一个 Provider 维护一把上游 API Key 与启用状态；同一供应商多账号用多个 Provider 表达。Admin 可一键导入 Provider / Model 模板，再补齐真实 Key 并挂载路由。
	</Card>
	<Card title="四种策略与 Provider 熔断" icon="warning">
		支持 `cache_affinity`、`weighted_random`、`fixed_order`、`weighted_round_robin`，并可按 Route Pool 的 priority 层覆盖。默认 cache_affinity 稳定首选上游以提高 Prompt Cache 命中；429、401 / 403 与连续 5xx 会触发 Provider 级冷却。
	</Card>
	<Card title="用户 Key、预算与计费" icon="padlock">
		External system → User → API Key 分层治理；预算与周期归属 User，调用由 API Key 鉴权和归集。模型请求同时记 **供应成本**、**目录标准价**、**用户计费**，并支持业务时区下的每日时段倍率。
	</Card>
	<Card title="日志、审计与 Analytics" icon="magnifier">
		请求日志记录协议 / operation、模型、route group、Surface、Pool、Target、Provider、token、状态和三类成本；审计日志记录预算扣减、周期重置与用户 / Key 生命周期。
	</Card>
	<Card title="Playground 与 Simulator" icon="open-book">
		Playground 在 Admin 内测试单条 route；Simulator 用真实用户 Key 模拟客户端调用，检查鉴权、路由、计费与日志链路。
	</Card>
	<Card title="部署与系统集成" icon="rocket">
		默认 **Cloudflare Workers + D1**（个人与小流量通常可在免费额度内运行）；也可 Node / Docker + PostgreSQL 或 MySQL 8。外部门户可通过 **`/api/admin/*`** 自动开通用户、发 Key、同步预算。
	</Card>
</CardGrid>
