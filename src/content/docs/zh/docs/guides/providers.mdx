在管理台左侧的推理（**Inference**）下打开供应商（**Providers**）页面。一个 Provider 表示一个上游服务账号，包含协议端点、一把上游 API Key 及启用状态。页面以卡片展示密钥状态、活动路由数和协议能力，并支持按状态及 OpenAI、Anthropic、Gemini、DashScope 协议筛选。

<Aside type="tip" title="前置">
	请先完成 [快速开始](/zh/docs/quick-start/)，能登录管理台。
</Aside>

## 在管理台里要做什么

<Steps>
1. 在侧栏**推理（Inference）**下进入供应商（**Providers**）。
1. **新建或编辑**：填写名称、一把 **API Key**、状态与可选说明，再按协议分页配置 Base URL 或独立端点。OpenAI Responses 可填写独立端点，也可根据 OpenAI Base URL 派生 `/v1/responses`。
1. **多个账号**：同一供应商有多把账号密钥时，为每个账号创建一个供应商条目，再在同一路由池（**Route Pool**）中添加多个上游目标（**Upstream Target**）；`priority`、`weight` 与分流策略在 [路由配置](/zh/docs/guides/routing/) 中维护。
1. **从目录导入**：使用页面提供的模板目录快速预填协议端点；导入后仍需补全或核对 **API Key**。运行 Responses 或图片生成时，请确认卡片显示对应协议能力。
1. **保存后**：到 [路由配置](/zh/docs/guides/routing/) 把模型与供应商、协议类型关联起来；需要试连通时，可用[调试台（Playground）](/zh/docs/features/playground/)或[模拟器（Simulator）](/zh/docs/features/simulator/)。
</Steps>

## Gemini 内容生成

标准 Gemini 服务只需把 Base URL 配置到 `{model}` 之前，例如 `https://generativelanguage.googleapis.com/v1beta/models`。对于非标准上游，请在 URL 覆盖（**URL overrides**）中使用单一 `models.generate` 模板，形如 `https://example.com/v1beta/models/{model}:{action}`；`{action}` 会在运行时替换为 `generateContent` 或 `streamGenerateContent`。历史双模板仍可兼容读取，但新配置应使用统一模板。

## 常见注意点

- **Base URL / 端点**填写错误时容易出现 404、401，请与上游文档逐项对照。
- 本页**没有**“一键测试连接”按钮；请在配好路由后使用调试台或模拟器验证连通性。
- 上游轮换密钥后，请在本页替换并保存；需要灰度或备用账号时，请使用多个供应商条目与上游目标。
