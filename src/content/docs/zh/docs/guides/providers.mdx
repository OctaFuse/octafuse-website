供应商（Providers）中的一条记录代表一个上游账号：协议端点、一份凭证和启用状态。同一平台的多个账号使用多条记录，再放进对应路由池。

## 导入并连接上游

1. 从[供应商目录](/zh/catalog/providers/)选择普通按量、Coding / Token Plan 或私有兼容服务；套餐端点不要与按量模板混用。
2. 补齐真实凭证和项目、区域或资源名。普通 API Key 与 Vertex AI 的服务账号 JSON 是不同凭证类型。
3. 按实际需要配置 OpenAI、Anthropic、Gemini、DashScope、MiniMax、火山方舟或 ElevenLabs 端点。
4. Base 模式仅适合该上游覆盖相应能力的情况；部分支持时选择独立端点，避免派生出不存在的地址。
5. 配好[模型与路由](/zh/docs/guides/routing/)后，用调试台验证单条上游，再验证真实代理调用。

## 与官方模板比较更新

管理员在供应商页点击「同步」手动触发：先比对官方模板与已导入供应商的差异，确认后才应用。出现差异时，按字段比较介绍与端点，选择采用官方值或保留本地值；保存前查看受影响的路由。导入新版本目录不会自动覆盖已有账号的凭证和配置。

模型的目录更新在[模型页](/zh/docs/guides/models/)单独处理。运行状态与余额检查见[供应商额度](/zh/docs/guides/provider-quotas/)。

## Gemini 与 Vertex AI

Gemini 端点支持 query-key 或 Bearer 鉴权；项目级 Vertex AI 使用服务账号换取访问令牌。导入项目级模板后替换项目与区域占位符，并按模板要求填写完整服务账号 JSON。

原生 Gemini 内容生成使用统一的 `models.generate` 模板，流式和非流式在运行时选择对应 action。供应商端点、鉴权和 URL 覆盖的准确写法见 [配置参考](https://github.com/OctaFuse/octafuse-gateway/blob/v2.19.0/docs/users/configuration.md)。

## 日常变更

更换密钥、地址或区域后先测试连通性。删除供应商前检查关联路由；路由删除会立即生效，不能依赖关闭编辑弹窗撤销。上游账号仍存在不代表它的所有模型和操作均可用。
