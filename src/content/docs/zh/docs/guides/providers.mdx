在管理台左侧打开 **Inference → Providers**。**Provider** 表示一个上游服务账号：可为 **OpenAI 兼容**、**Anthropic**、**Gemini** 分别填写访问地址，并维护 **一把上游 API Key** 与 `active` / `disabled` 状态。需要同一供应商多个账号时，请创建多个 Provider。

<Aside type="tip" title="前置">
	请先完成 [快速开始](/zh/docs/quick-start/)，能登录管理台。
</Aside>

## 在管理台里要做什么

<Steps>
1. 在侧栏 **Inference** 下进入 **Providers**。
1. **新建或编辑**：填写名称、各协议的访问地址（`base` 或 capability 完整 URL；是否与 `/v1` 等路径拼接请严格按上游文档）、一把 **API Key**、状态与可选说明。
1. **多个账号**：同一供应商有多把账号 Key 时，为每个账号创建一个 Provider，再在同一 Route Pool 中添加多个 Upstream Target；priority、weight 与分流策略在 [路由配置](/zh/docs/guides/routing/) 中维护。
1. **从目录导入**：使用页面提供的模板目录，可快速预填各协议的访问地址；导入后仍需补全或核对 **API Key**。跑 Images 时请确认 generations（及需要时的 edits）端点；见 [Images](/zh/docs/guides/images/)。
1. **保存后**：到 [路由配置](/zh/docs/guides/routing/) 把模型与供应商、协议类型关联起来；需要试连通时，可用 [Playground](/zh/docs/features/playground/) 或 [Simulator](/zh/docs/features/simulator/)。
</Steps>

## Gemini Generate Content

标准 Gemini 服务只需把 Base URL 配到 `{model}` 之前，例如 `https://generativelanguage.googleapis.com/v1beta/models`。非标准上游在 Advanced 中使用单一 **`models.generate`** 模板，形如 `https://example.com/v1beta/models/{model}:{action}`；`{action}` 会在运行时替换为 `generateContent` 或 `streamGenerateContent`。历史双模板仍可兼容读取，但新配置应使用统一模板。

## 常见注意点

- **Base URL / endpoints** 填错容易出现 404、401，请与上游文档逐项对照。
- 本页**没有**「一键测试连接」按钮；连通性请在配好路由后用 Playground / Simulator 验证。
- 上游轮换密钥后，请在本页替换并保存；需要灰度或备用账号时使用多个 Provider 与 Route Target。
