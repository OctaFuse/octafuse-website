额度决定还能调用多少，价格决定一次调用扣多少。先确认[系统配置](/zh/docs/guides/system-config/)中的计费币种与业务时区，再为用户设置额度和折扣。

## 周期额度与永久额度

| 额度 | 适用场景 | 消费与重置 |
|---|---|---|
| 周期额度 | 按日、周或月发放的套餐 | 按用户周期规则重置 |
| 永久额度 | 加购、注册赠额、退款或补偿 | 不随套餐周期自动清零 |

一次调用先消耗周期额度，不足部分再从永久额度扣除。周期额度上限为 `0`、永久额度仍有余额时，用户依然可以调用。周期不限额时，总剩余可能显示为不限额。

![用户详情中的周期额度与永久额度](/screenshots/v2-8-0-user-dual-quota.webp)

日常加购应通过 Admin 的永久额度加额接口完成，并传入唯一业务流水号保证幂等；不要通过反复增加周期预算发放购买额度。接口契约见 [Admin API](https://github.com/OctaFuse/octafuse-gateway/blob/v2.18.0/docs/developers/api/admin.md)。

## 三种金额各自代表什么

- **目录标准价（Standard）**：模型的目录价与命中的模型官方时段规则。
- **供应成本（Metered）**：本次向上游供应商支付的估算成本。
- **用户计费（Charged）**：本次向用户计算的费用，用于扣减额度。

路由可分别设置用户计费与供应成本倍率；供应商倍率在其有效期内作用于两侧，不改变目录标准价。官方时段与路由时段也应分开维护。保存前查看价格预览，调用后用[请求日志](/zh/docs/guides/request-logs/)核对当次快照。

## 用户折扣不是只有相乘

用户可以按模型设置统一倍率，也可以为同一模型的不同路由组分别设置倍率。具体分组优先，`*` 用作其余分组兜底；未匹配时保持路由价格。

网关配置 `USER_CHARGED_COST_FACTOR_MODE` 决定合成方式：

| 模式 | 作用 | 路由有效倍率 0.8、用户倍率 0.5 |
|---|---|---|
| `multiply`（默认） | 两个倍率相乘 | 最终倍率 0.4 |
| `min` | 取两者较小值 | 最终倍率 0.5 |

最终用户费用基于**官方当刻目录价 × 合成后的用户计费倍率**。用户折扣不会修改供应成本；字段级规则见 [用户 API 与计费语义](https://github.com/OctaFuse/octafuse-gateway/blob/v2.18.0/docs/developers/api/user.md)。

![按模型与路由组配置用户倍率](/screenshots/v2-14-0-user-group-factors.webp)

## 模型与工具分别定价

文本与向量通常按 Token；图片按其目录配置使用 Token 或按张计费；音频可能按 Token、时长或字符计费。以所选模型和适配器的实际用量为准。

REST 工具与 MCP 使用自己的标准价和倍率，不套用模型路由时段或用户模型折扣。MCP 当前只按成功工具调用次数计费；REST 搜索按请求，AI 检测按配置的字符单元。

## 配好后怎么验证

1. 在用户详情核对周期、永久额度与模型分组倍率。
2. 用模拟器或真实客户端发一次请求。
3. 在请求流程的「用量与记账」核对费用，再看账户审计中的两种额度变化。
4. 调用用户侧 `GET /v1/me`，确认余额变化符合预期。
