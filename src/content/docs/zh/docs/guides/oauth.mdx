OAuth 适用于希望用户在 MCP 客户端登录授权、而不是手动粘贴用户 Key 的场景。**先准备与网关完成对接的授权服务器**：它负责登录、同意授权、刷新以及通过 Admin API 签发和轮换网关访问令牌。

## 启用前的边界

OctaFuse Gateway 是资源服务器，不提供授权服务器。填写普通登录页地址不能完成对接。业务账号还需要关联到对应的网关用户，调用费用才有明确归属。

现有 API Key 接入可以继续使用。OAuth 不是所有模型接口的通用登录方式，也不会把上游服务的 OAuth 自动转接给客户端。

## 开启授权发现

1. 打开 MCP 服务页的「客户端接入」分区，找到「OAuth 2.0 授权登录（可选）」卡片。
2. 启用「OAuth 2.0 授权登录」，填写授权服务器的 HTTPS 源地址并保存；本机开发允许 HTTP localhost。
3. 在接入指南中切换到 OAuth，按对应客户端的步骤连接。
4. 完成一次授权和工具调用，确认请求日志中的应用名与所属用户正确。

## 令牌、刷新与撤销

- MCP 访问令牌以 `oat_` 开头，与用户 API Key 分开存储，只能访问 `/mcp` 和其子路径。
- 默认有效期 1 小时。令牌过期后，客户端可通过授权服务器刷新；不意味着每小时都必须重新登录。
- 在「OAuth 访问令牌」中可按用户或应用查看和撤销；用户详情也能查看该用户的授权。
- 关闭授权服务器设置会关闭 OAuth 发现；要阻止已签发令牌继续使用，需要撤销对应令牌。

## 排查授权问题

先确认授权服务器已完成协议与令牌签发对接，再检查资源发现地址、客户端回调和令牌状态。401 通常需要重新取得有效令牌；用 MCP 令牌调用聊天等其他接口会因作用域不匹配被拒绝。

对接 API、发现元数据和刷新职责见 [OAuth 技术参考](https://github.com/OctaFuse/octafuse-gateway/blob/v2.19.0/docs/developers/architecture/mcp-gateway.md#oauth-授权发现)。
