请求日志（Request Logs）记录经过代理服务的真实调用，包括模型请求、REST 工具和 MCP 工具调用（原「调用记录」已并入这里），位于侧栏「日志」分组。调试台直连上游不会生成用户请求日志；模拟器与真实客户端会。

## 按类型、模型与供应商筛选

「类型」「模型」「供应商」都是两级多选，勾选项取并集：

- **类型**分为模型（LLM、图像、ASR、TTS、向量）与工具（各 REST 工具、各 MCP 服务），例如可以同时查看图像请求和某个工具的调用。
- **模型**按厂商分组，**供应商**按类型分组，可以勾选整组或其中几项，面板内可搜索。
- 选了多项时，筛选栏下方逐项列出，可单独移除。筛选之间会联动：范围里只有工具调用时，模型、供应商、协议和路由组筛选不适用。

## 从一次错误开始

1. 用客户端返回的请求 ID 精确查询，或按时间、用户、模型、供应商、路由组和状态筛选。
2. 核对入站入口与实际上游，避免把最终供应商误认为唯一尝试过的供应商。
3. 展开请求流程，按处理阶段定位：请求入站 → 路由与转换 → 上游尝试 → 响应结果 → 用量与记账。
4. 点击阶段或具体尝试，查看参数变化、HTTP 状态、失败类别、路由信息及原始快照。

[![请求流程展示首次 429 后切换并成功](/screenshots/v2-18-0-request-detail-failover.png)](/screenshots/v2-18-0-request-detail-failover.png)

时间线按实际记录显示各次尝试和等待耗时。缺失耗时不是零耗时；上游尝试耗时与完整流式输出耗时也不是同一指标。

常用筛选按页面宽度展开，精确 ID 等条件按需查看。时间范围按业务时区选择，可以只设起点或终点，也可以不限时间；列表金额之后保留计费与成本倍率。上游返回 HTML 错误页时，列表只显示摘要，完整内容在请求详情里。需要盯着新请求时，可以开启自动刷新（10 秒到 5 分钟），阅读列表时新日志会先提示再展示。

## 工具调用详情

工具调用的详情按调用概览、请求、响应、记账展示，不套用模型的请求流程。REST 工具列出引擎、请求参数与结果；MCP 工具列出服务、上游工具、调用参数与返回内容。请求和响应区域可在右上角切换「预览」与「原始数据」。调用失败时，顶部给出错误原文与排查方向，可直接打开对应的工具配置或 MCP 服务。

## 核对收费

「用量与记账」区分用户计费、供应成本和当次价格快照。核对目录官方时段、供应商倍率、路由窗口、用户模型与分组倍率，不用当前配置重新推算历史账单。

周期与永久额度的实际变化在[账户审计](/zh/docs/guides/audit-logs/)查看。金额和业务日界受全局币种、业务时区影响。

## MCP 与粘性排障

MCP 来源可按服务筛选，OAuth 调用会标明应用；费用归属令牌所属用户。粘性路由可结合绑定命中、解绑或重绑结果，与缓存读取用量和故障转移次数一起观察。

单条请求说明“这次发生了什么”；跨请求趋势和供应商质量阅读[用量与可靠性分析](/zh/docs/guides/analytics/)。底层字段见 [日志 API 参考](https://github.com/OctaFuse/octafuse-gateway/blob/v2.20.0/docs/developers/api/admin.md)。
