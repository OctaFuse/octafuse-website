	需要已有流量经过**网关代理**。[调试台（Playground）](/zh/docs/features/playground/)的试跑方式**不会**出现在本日志中；若要产生与线上一致的记录，请用真实密钥调用网关代理或使用[模拟器（Simulator）](/zh/docs/features/simulator/)。

## 在管理台里要做什么

<Steps>
1. 打开**请求日志**。
1. 使用时间范围、状态、模型、用户邮箱、API 密钥、供应商、路由组、协议等条件缩小范围（以页面筛选项为准）。
1. 点击展开某一行，查看计费核对摘要、入口请求体、上游请求体、用量原始 JSON 等（可复制）。
1. 核对金额与时间时，请与你在 **系统配置** 中设置的业务时区、计费币种保持一致理解。
</Steps>

## 与计费展示的关系

展开区域可能包含与扣费相关的多段 JSON 摘要；若需精确公式或与账单对账，请结合主仓库文档或内部财务口径。

## 观察供应商粘性

路由池启用供应商粘性（Provider sticky）后，展开日志中的 `route_trace.sticky`：

- `lookup`：绑定读取结果，例如 `hit`、`miss`、`expired`、`invalid_epoch`、`invalid_target` 或 `invalid_circuit`。
- `attempted_target`：本次优先尝试的绑定上游目标（Target）。
- `result`：绑定最终保持、清除、新建或重绑，也可能记录 `storage_error` / `unchanged`。

将供应商粘性命中情况与缓存读取 Token、上游故障转移次数结合观察：命中稳定但缓存收益没有改善时，应检查上游是否真正共享提示词缓存（Prompt Cache）；频繁出现 `cleared` / `rebound` 时，应检查供应商返回的 429、5xx、鉴权错误与 TTL 是否合理。
