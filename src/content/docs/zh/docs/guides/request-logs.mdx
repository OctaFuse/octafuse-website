请求日志（Request Logs）记录经过代理服务的真实调用。调试台直连上游不会生成用户请求日志；模拟器与真实客户端会。

## 从一次错误开始

1. 用客户端返回的请求 ID 精确查询，或按时间、用户、模型、供应商、路由组和状态筛选。
2. 核对入站入口与实际上游，避免把最终供应商误认为唯一尝试过的供应商。
3. 展开请求流程，按处理阶段定位：请求入站 → 路由与转换 → 上游尝试 → 响应结果 → 用量与记账。
4. 点击阶段或具体尝试，查看参数变化、HTTP 状态、失败类别、路由信息及原始快照。

[![请求流程展示首次 429 后切换并成功](/screenshots/v2-18-0-request-detail-failover.png)](/screenshots/v2-18-0-request-detail-failover.png)

时间线按实际记录显示各次尝试和等待耗时。缺失耗时不是零耗时；上游尝试耗时与完整流式输出耗时也不是同一指标。

## 核对收费

「用量与记账」区分用户计费、供应成本和当次价格快照。核对目录官方时段、供应商倍率、路由窗口、用户模型与分组倍率，不用当前配置重新推算历史账单。

周期与永久额度的实际变化在[账户审计](/zh/docs/guides/audit-logs/)查看。金额和业务日界受全局币种、业务时区影响。

## MCP 与粘性排障

MCP 来源可按服务筛选，OAuth 调用会标明应用；费用归属令牌所属用户。粘性路由可结合绑定命中、解绑或重绑结果，与缓存读取用量和故障转移次数一起观察。

单条请求说明“这次发生了什么”；跨请求趋势和供应商质量阅读[用量与可靠性分析](/zh/docs/guides/analytics/)。底层字段见 [日志 API 参考](https://github.com/OctaFuse/octafuse-gateway/blob/v2.18.0/docs/developers/api/admin.md)。
