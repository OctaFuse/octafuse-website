模型（Models）维护客户端可识别的模型 ID、厂商、输入输出模态与目录价。供应商实际模型名在路由中映射，客户端不必跟着上游名称变化。

## 导入和配置

1. 从[模型目录](/zh/catalog/models/)导入，或新建自定义模型。
2. 核对模型类型：LLM、图片、语音识别、语音合成或向量；类型由模态和计费规则共同判定。
3. 维护上下文、最大输出、发布日期、备注和目录价格。标签由管理员维护，导入不自动创建路由。
4. 在[路由](/zh/docs/guides/routing/)中添加至少一个可用上游和已启用入口，再执行真实调用。

## 与官方目录同步

管理员手动点击「同步」，先比对再确认应用，逐项比较模型名称、模态、规格、介绍与价格。可对单模型或批量选择采用官方值或保留当前值；**价格默认保留，应用前核对受影响的路由**。官方未提供的字段不会据此清空本地值。

![模型官方目录逐项对比与同步](/screenshots/v2-15-0-model-official-sync.webp)

已导入模型与官网静态目录属于不同数据：更新静态目录不会悄悄改写部署中的价格、标签或路由。

## 模型类型与计费

| 类型 | 核对重点 |
|---|---|
| LLM | 输入、输出和缓存价，长上下文档位与官方时段 |
| 图片 | Token 或按张模式，尺寸、质量及参考图等价格条件 |
| ASR / TTS | 秒、字符或 Token 计费，与适配器实际用量匹配 |
| 向量 | 输入 Token 单价，默认模型列表不包含向量 |

## 三个发现入口

- 官网目录：正式版本的导入预设，可包含尚未在你部署中启用的模型。
- 你的网关 `GET /catalog/models`：公开发现有活跃路由的能力。
- 用户 `GET /v1/models`：客户端模型列表；默认 LLM，其他类型使用 `kind=image/asr/tts/embedding` 等筛选。

协议、模态和类型判定见 [模型类型参考](https://github.com/OctaFuse/octafuse-gateway/blob/v2.19.0/docs/developers/reference/model-kinds.md)；[接入客户端](/zh/docs/guides/clients/)说明模型 ID 和路由组的写法。
