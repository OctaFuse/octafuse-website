先确定客户端使用哪种入口，再选择兼容的上游适配器。**OpenAI Images 是客户端协议，不要求实际上游也使用 OpenAI 协议。**

## 选择接入路径

| 路径 | 配置方式 | 需要注意 |
|---|---|---|
| OpenAI 兼容生成 / 编辑 | 配置对应 OpenAI 请求入口和兼容端点 | 生成与 multipart 编辑分别检查 |
| OpenAI 入口 → 厂商图片接口 | 选择 DashScope、MiniMax、火山方舟 / BytePlus 或 Gemini 图片适配器 | 仅支持适配器声明的操作与参数；生成不等于支持 edits |
| 厂商原生入口 | 使用已实现的原生协议与透传适配器 | 请求、响应和流式能力按该协议处理 |

## 完成配置

1. 在供应商中配置实际需要的原生或兼容端点及凭证；部分支持的能力应填写独立端点，避免从 Base 派生不存在的接口。
2. 导入图片模型，核对输出模态与 `image_billing_mode`。`token` 按实际用量，`per_image` 按成功张数及所配档位计费。
3. 在路由中选择协议适配器，检查客户端入口、上游操作、模型名和参数映射。
4. 先在调试台试跑单条上游，再用模拟器验证真实调用与记账。

## 最小客户端请求

```bash
curl -sS http://localhost:8787/v1/images/generations \
  -H 'Authorization: Bearer sk-your-api-key' \
  -H 'Content-Type: application/json' \
  -d '{"model":"your-image-model","prompt":"a watercolor lighthouse","n":1}'
```

图片模型列表使用 `GET /v1/models?kind=image`。图片编辑使用 `/v1/images/edits`，仅在所选上游与适配器支持时可用；有些生成入口使用 JSON 参考图完成图生图，与 multipart 编辑不同。

**GPT Image 2.6**（`gpt-image-2.6-flare`、`gpt-image-2.6-sunburst`）只支持 Images API 的 generations 与 edits，不能作为 Chat Completions 或 Responses 的主模型。`complexity` 作为客户端额外字段转发，不要写成路由默认值；`svg` / `gif` 输出格式及 GIF 的 `frame_count`、`frame_duration_ms` 同样作为额外字段转发，且只用于 generations。edits 不支持这两种格式，edits 里的 markup 文件目前也不会转发。

## 计费与结果检查

成功后核对返回图片、张数、用量和当次价格快照。客户端取消、网关超时、明确的上游错误或空结果不扣用户额度；不要将“按图片输出”误解为所有模型均按张计费。

模型参数、尺寸档位、原生路径和不扣费边界见 [图片技术参考](https://github.com/OctaFuse/octafuse-gateway/blob/v2.19.0/docs/developers/reference/image-models.md) 与 [厂商覆盖矩阵](https://github.com/OctaFuse/octafuse-gateway/blob/v2.19.0/docs/developers/reference/native-provider-coverage.md)。
