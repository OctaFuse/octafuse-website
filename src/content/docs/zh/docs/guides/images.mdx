网关对外提供 OpenAI 兼容的 **`POST /v1/images/generations`** 与 **`POST /v1/images/edits`**（multipart）。鉴权与聊天请求相同（用户 `sk-…`）；模型须挂载**已启用的 OpenAI 协议路由**，并在目录中配置图片计价。

<Aside type="tip" title="前置">
	请先完成[供应商（Providers）](/zh/docs/guides/providers/)（含图片生成端点）与[模型（Models）](/zh/docs/guides/models/)配置。字段级契约见 [GitHub 技术参考 · image-models](https://github.com/OctaFuse/octafuse-gateway/blob/main/docs/developers/reference/image-models.md)。
</Aside>

## 在管理台里要做什么

<Steps>
1. **供应商**：为 OpenAI 或兼容上游配置密钥；`endpoints.openai.base` 可派生 `…/images/generations`，也可填写完整的 `images.generations` URL。Seedream 等不支持 OpenAI 编辑接口形态的上游**不要**填写 `base`（避免派生出无效的编辑接口地址）。
1. **模型**：导入或手动创建图片生成预设（`output` 含 `image`）。确认 `image_billing_mode`：
	- **`token`**：按上游 `usage` 中的图片 / 文本 Token 分项计价（如 GPT Image）。
	- **`per_image`**：按张目录价（如 Seedream），可选参考图输入单价。
1. **路由（Routes）**：为该模型添加 **OpenAI** 协议且状态为**启用**的路由。
1. **验收**：在调试台（Playground）通过单条路由试生成图片（不计入用户账单）；再使用模拟器（Simulator）发起真实的网关代理请求，并在[请求日志（Request Logs）](/zh/docs/guides/request-logs/)中核对 `billing_kind`、图片数量与扣费。
</Steps>

## 与模型列表的关系

- 默认 **`GET /v1/models`**（需要用户密钥）只返回大语言模型（LLM），**不含**纯图片生成模型；可传 `kind=image` / `kind=all`。
- 门户的模型发现功能使用公开的 **`GET /catalog/models`**（无需密钥），与 `/v1/models` 分工不同。

## 客户端最小示例

```bash
curl -sS "$GATEWAY_URL/v1/images/generations" \
  -H "Authorization: Bearer sk-your-api-key" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-image-2","prompt":"a watercolor fox","size":"1024x1024"}'
```
