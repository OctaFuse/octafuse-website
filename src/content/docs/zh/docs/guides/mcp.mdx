在 MCP 服务（MCP Servers）中，把远程 Streamable HTTP 服务接入网关。客户端可以通过 `/mcp` 使用全部已启用服务，或通过 `/mcp/服务标识` 只访问一个服务。

## 接入、审核和发布

1. 新建服务，填写服务标识、远程地址和所需静态请求头。也可导入支持的远程客户端 JSON。
2. 测试连接并手动同步目录，查看工具、提示词和资源。
3. 审核目录：新条目默认停用；已发布条目的说明或参数变更需要审核后才替换客户端定义。
4. 为服务配置默认价格，需要时为单个工具设置独立价格。
5. 启用要公开的条目，再使用「对外目录测试」确认客户端实际看到的清单。

![MCP 服务与目录管理](/screenshots/v2-15-0-mcp-services.webp)

## 配置客户端

使用「接入指南」选择代理服务地址、全部服务或单服务，再复制对应客户端的配置。支持用户 API 密钥的客户端可以直接连接；需要登录授权的客户端请先完成 [OAuth 对接](/zh/docs/guides/oauth/)。

![MCP 接入指南](/screenshots/v2-15-0-mcp-connection-guide.webp)

「对外目录测试」只查询目录和协议能力，不执行工具，也不验证实际工具结果。完成配置后，应再用真实客户端调用一个工具并核对请求日志。

## 收费与观察

当前 MCP 按成功的 `tools/call` 次数计费，标准价分别乘用户倍率和供应倍率；用户倍率为 `0` 表示用户免费，仍记录供应成本。提示词与资源读取不计费。工具独立价格整组覆盖服务默认价格，不套用模型折扣。

调用在请求日志中以 MCP 来源记录，OAuth 调用还会标明应用。没有可用工具结果、工具报错或上游失败时不扣费。

## 支持边界

- 不在网关托管本地 stdio 进程，不自动转换内置 REST 服务。
- 导入连接配置不会导入上游 OAuth 流程；上游接入使用支持的远程地址和静态鉴权方式。
- 对外为无会话的 Streamable HTTP；不支持上游反向发起的 sampling、elicitation、roots。
- 不接受 JSON-RPC 批量数组，应逐条发送请求。

完整生命周期、命名空间与计费语义见 [MCP 架构参考](https://github.com/OctaFuse/octafuse-gateway/blob/v2.18.0/docs/developers/architecture/mcp-gateway.md)。
