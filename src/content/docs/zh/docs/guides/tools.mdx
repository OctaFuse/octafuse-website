REST 服务（REST Services）通过 `/v1/tools/*` 为应用和 Agent 提供独立工具 API。它们不是模型对话协议的一部分；模型产生工具调用后，由客户端执行对应工具请求。

| 服务 | 入口 | 已实现引擎示例 |
|---|---|---|
| 网页搜索 | `/v1/tools/web-search` | 博查、Tavily、CleverSee、腾讯云 WSA、DeepSeek |
| 网页抓取 | `/v1/tools/web-fetch` | Firecrawl、Tavily Extract、Jina Reader、DeepSeek |
| 深度搜索 | `/v1/tools/web-deep-search` | Firecrawl Search、Jina Search、DeepSeek |
| AI 率检测 | `/v1/tools/ai-detection` | 腾讯云 TMS |

## 配置与启用

1. 在「工具」分组下打开 REST 服务，按名称、服务类型或状态筛选，点击服务进入工作区。
2. 在「供应商与计费」中展开供应商查看介绍与接入要点，点击配置填写第三方凭证与计费规则并保存；未保存的修改可以还原。
3. 设置标准价、用户倍率与供应倍率，核对收费和成本预览。搜索按请求计费，AI 检测按配置的字符单元计费。
4. 在供应商列表的「使用状态」列启用所需供应商。每种工具当前只有一个活跃引擎；有未保存修改或凭证不全时不能启用。
5. 用用户密钥调用真实代理入口，再到请求日志查看结果：类型筛选选择对应的 REST 工具，详情会列出引擎、请求参数、结果与记账。

用户倍率设为 `0` 时用户免费，仍记录供应成本。REST 服务不应用模型路由时段或用户模型折扣；旧独立单价配置兼容读取，新保存规则使用标准价与倍率。

## 使用 DeepSeek 引擎

DeepSeek 引擎对接 DeepSeek 独立的 Search / Fetch API，三个服务各自配置，分别填入 DeepSeek API Key（可以是同一个），对外接口不变。使用前注意：

- 查询词最长 128 个字符，超出部分由 Gateway 截断。
- 域名白名单 / 黑名单能放进查询词时以 `site:` / `-site:` 下发，放不下时多取结果后在本地过滤。
- 深度搜索一次请求即可取回正文。
- 上游按每千次成功请求 $0.75 计价，请自行设置标准价与倍率；Gateway 对空结果仍按次计费。

## 一次搜索请求

```bash
curl -sS http://localhost:8787/v1/tools/web-search \
  -H 'Authorization: Bearer sk-your-api-key' \
  -H 'Content-Type: application/json' \
  -d '{"query":"OctaFuse gateway","count":5}'
```

上游失败不扣用户额度；未配置可用活跃引擎时，调用不能成功。想接入外部标准化工具协议，阅读 [MCP 服务](/zh/docs/guides/mcp/)；REST 工具不会自动作为 MCP 暴露。

各服务字段与引擎限制见 [工具 API 参考](https://github.com/OctaFuse/octafuse-gateway/blob/v2.21.0/docs/developers/api/user.md)。
