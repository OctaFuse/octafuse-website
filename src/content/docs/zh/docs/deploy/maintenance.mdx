在系统 → 维护模式（Maintenance）中设置维护时间与提示。适合迁移、切换或维护窗口；它不会自动为你执行数据库迁移。

## 开启后的行为

| 对象 | 行为 |
|---|---|
| 新的模型、工具、MCP 和实时连接请求 | 返回 503，带维护标识与重试提示；拒绝发生在鉴权之前，不写请求日志、不扣费、不占 RPM |
| 健康检查和模型、额度、目录等只读入口 | 继续可用；`/health` 仍返回 200，并带维护状态 |
| 已开始的流式请求 | 继续运行，结束后按原规则记账 |
| 管理端写入 | 可选冻结，默认开启；维护开关等必要例外仍可操作 |

![维护模式配置](/screenshots/v2-17-0-maintenance.webp)

## 维护窗口步骤

1. 设置预计时长和中英文提示，确认是否同时冻结管理写入。
2. 开启后确认后台维护横幅及新请求的响应；各进程配置缓存会带来短暂生效延迟。
3. 等待在途调用完成，再按目标版本参考执行迁移或切换。
4. 维护结束后在实际承接流量的新环境关闭维护，并发送一条真实请求。

配置读取失败时采用放行行为；维护模式不能替代数据库或网络层的强制隔离。跨数据库迁移可能复制维护配置，切换后需要明确检查。

完整例外接口、权限与运行语义见 [维护模式参考](https://github.com/OctaFuse/octafuse-gateway/blob/v2.18.0/docs/operators/maintenance-mode.md)。
