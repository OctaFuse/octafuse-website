Docker 适合自有主机、私有网络或容器平台，数据库可选 Postgres 或 MySQL。第一次本地启动见[快速开始](/zh/docs/quick-start/)；与另一种运行环境比较见[部署选择](/zh/docs/deploy/overview/)。

## 选择运行模板

| 需求 | 仓库内模板 |
|---|---|
| 本地完整体验 | `docker/compose/quickstart.yml` |
| 自托管 Postgres | `docker/compose/node-pg.yml` |
| 自托管 MySQL | `docker/compose/node-mysql.yml` |
| 外置数据库与预构建镜像 | `docker/examples/` |

选择同版本的 Proxy、Admin 和 migrate 镜像；生产环境固定版本标签或摘要。数据库连接串由环境或 secret 提供，三类进程必须指向同一目标数据库。MySQL 还需明确选择对应数据库驱动。

## 首次部署顺序

1. 准备数据库、持久化与备份，并填写模板要求的环境变量。
2. 先运行一次性迁移任务，确认成功。
3. 启动 Proxy 和 Admin，再配置供应商、模型与路由。
4. 设置生产管理密码和具名集成密钥，使用 HTTPS 对外服务。

本地 quickstart 的 `admin / changeme` 只用于示例。不要将数据库凭证、管理密码或上游 Key 写入版本控制。

## 验收

检查 Proxy 的 `/health`，登录管理后台，再以专用测试用户发送一条真实调用。确认请求日志、用量与额度变化；使用实时音频时另测对应的 WebSocket 链路。

单独启动容器或健康检查成功，不表示模型和工具已经配置完成。

## 升级

先读目标版本的[升级说明](/zh/docs/deploy/upgrades/)，备份并规划维护窗口，执行待应用迁移后，再更新相同版本的服务。自动迁移只在明确选定的一侧启用，避免多个进程同时承担迁移职责。

实际 Compose 命令、镜像地址、环境变量和平台差异见 [Docker 部署参考](https://github.com/OctaFuse/octafuse-gateway/blob/v2.18.0/docs/operators/deployment/docker.md)。
