目标是完成一次 **客户端 → 网关 → 上游 → 日志与扣费** 的完整调用。先选择部署方式；两条路径之后使用相同的配置流程。

## 1. 启动网关

### Docker 本地体验

准备 Docker 和 Compose，克隆正式版本：

```bash
git clone --branch v2.18.0 --depth 1 https://github.com/OctaFuse/octafuse-gateway.git
cd octafuse-gateway
docker compose -f docker/compose/quickstart.yml up --build
```

该示例启动 Postgres、迁移任务、代理服务和管理后台。代理服务为 `http://localhost:8787`，管理后台为 `http://localhost:8789`，本地示例账号为 `admin / changeme`。

### Cloudflare 本地体验与部署

需要 Node.js、npm；在同一仓库执行：

```bash
npm install
npm run db:migrate
npm run dev:proxy
```

另开终端执行 `npm run dev:admin`。代理服务和管理后台分别在 `127.0.0.1:8787`、`127.0.0.1:8789`，本地默认账号为 `admin / admin`。上云步骤见 [Cloudflare 部署](/zh/docs/deploy/cloudflare/)。

以上登录信息仅用于本地示例。生产部署、密码和数据落点的选择见[部署方式](/zh/docs/deploy/overview/)。

## 2. 配置一个模型

1. 在供应商（Providers）中导入一个实际使用的供应商，填写自己的上游凭证，核对协议端点。
2. 在模型（Models）中导入一个该供应商可调用的模型。导入仅创建模型记录。
3. 在路由（Routes）中添加上游目标，选匹配的协议适配器，填写实际的上游模型名。初次使用保留 `default` 路由组。
4. 在调试台（Playground）测试这条上游路由，确认地址、凭证和模型可用。
5. 创建用户，为其设置[周期额度或永久额度](/zh/docs/guides/billing/)，再创建用户 API 密钥。

## 3. 发送第一次真实请求

```bash
curl -sS http://localhost:8787/v1/chat/completions \
  -H 'Authorization: Bearer sk-your-api-key' \
  -H 'Content-Type: application/json' \
  -d '{"model":"your-route-model","messages":[{"role":"user","content":"Hello"}]}'
```

将模型名和密钥替换为自己的配置；上云后替换代理服务地址。Chat 请求需要已启用的 Chat 请求入口；Responses 等协议应使用对应入口与请求格式。

## 4. 确认整条链路

- 返回模型内容：确认真实请求已通过网关。
- 打开[请求日志](/zh/docs/guides/request-logs/)：查看实际供应商、上游尝试、用量与记账。
- 调用 `GET /v1/me` 并携带用户密钥：核对周期额度、永久余额与总剩余额度。

调试台的直连测试不生成这些用户调用记录。也可以使用[模拟器](/zh/docs/features/simulator/)完成上述验证。
