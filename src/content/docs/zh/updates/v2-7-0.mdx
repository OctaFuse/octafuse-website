OctaFuse Gateway 2.7.0 重点解决三个实际问题：如何让工作日和周末使用不同价格，如何为不同用户设置专属模型价格，以及如何通过统一网关调用阿里云百炼的同步多模态语音识别。

这意味着，当模型供应商调整峰谷计费规则时，你可以直接在路由中跟进；面对签约客户、内部账号或不同服务套餐，也可以为指定模型单独设置折扣或加价。

一句话看懂 2.7.0：

> **价格可以按星期和时段变化，也可以因用户和模型而不同；同时补齐百炼同步多模态语音识别。**

## 01｜第一时间支持 DeepSeek 周末全天低谷价

DeepSeek 自北京时间 **2026 年 8 月 23 日（周日）00:00** 起调整峰谷计费规则：工作日高峰时段仍为 `09:00–12:00`、`14:00–18:00`，其余时段按高峰价格的一半计费；周六、周日全天统一按低谷价格计费。

2.7.0 的路由时段可以选择在星期几生效。以低谷价作为模型目录标准价时，只需要完成三项配置：

- 路由默认倍率保持为 **`1`**，代表正常使用低谷价。
- 添加 `09:00–12:00`、`14:00–18:00` 两个高峰时段，倍率均设为 **`2`**。
- 两个高峰时段都只选择 **周一至周五**。

工作日其他时间和周末全天不会进入高峰时段，因此会自动回到 `1` 倍的低谷价，不需要再为周末逐段添加规则。

![OctaFuse 路由编辑器为 DeepSeek V4 Flash 配置分时计价与星期选择](/screenshots/v2-7-0-route-weekday-schedule.webp)

*新版时段编辑器提供“每天”“工作日”“周末”快捷选择，也可以逐日调整。图中展示的是每天生效；适配 DeepSeek 新规则时，应将两个高峰时段改为仅周一至周五生效。*

页面中的“供应成本”（Metered）和“用户计费”（Charged）可以分别设置。如果只想准确记录 DeepSeek 向你收取的费用，只需调整供应成本；如果还想把相同的峰谷价格提供给用户，再同步调整用户计费。

DeepSeek 路由的业务时区应设为 `Asia/Shanghai`。价格在请求进入网关时确定，因此长时间的流式请求即使跨过高峰与低谷分界，也不会在请求过程中突然改变价格。

已有配置可以放心升级：没有选择星期的旧时段仍会每天生效。跨午夜时段也继续支持，例如周五 `22:00–06:00` 表示从周五晚上持续到周六早上 6 点。

## 02｜为不同用户设置专属模型价格

同一个模型往往需要面向不同用户提供不同价格。例如，签约客户享受八折，合作伙伴享受五折，内部测试账号免费，而普通用户继续使用标准价格。

2.7.0 可以在用户详情中为每个模型单独设置倍率。最终向用户收取的费用可以理解为：

> **目录标准价 × 路由用户计费倍率（包含峰谷时段）× 用户专属模型倍率**

设置 `0.8` 代表八折，设置 `0.5` 代表五折，设置 `0` 则该用户使用这个模型时不计费；没有单独设置的模型仍按原价计算。用户专属倍率只影响最终收费和预算消耗，不会改变模型目录价格，也不会影响供应商实际向你收取的成本。

![OctaFuse 用户详情页按模型维护 Charged cost factors](/screenshots/v2-7-0-user-charged-cost-factors.webp)

*在用户详情中选择模型并填写倍率。未添加的模型保持原价，填写 0 表示该模型不向当前用户计费。*

用户列表也会显示已消费金额、预算上限、下次重置时间、可用密钥数量和模型价格摘要，方便快速了解每个用户的套餐状态。

需要通过自己的管理系统批量维护时，也可以使用管理接口（Admin API）写入 `charged_cost_factors`：

```json
{
  "charged_cost_factors": {
    "deepseek-v4-pro": 0.8,
    "deepseek-v4-flash": 0.5
  }
}
```

系统会拒绝不存在的模型、负数或格式错误的数据。这套规则适用于大语言模型、图片和音频请求；智能体工具继续使用自己的独立价格，不受用户模型倍率影响。

请求日志会保存实际使用的用户倍率、业务时区中的星期和命中的计价时段。如需排查金额，可以沿着“目录价—路由价格—用户专属价格”逐层核对。

## 03｜新增百炼同步多模态语音识别

2.7.0 新增阿里云百炼（DashScope）同步多模态语音识别接口。应用提交请求后，可以在同一次响应中取得识别结果，并继续使用 OctaFuse 现有的密钥、预算、路由、日志和计费能力。

接口地址为：

```text
POST /v1/dashscope/services/aigc/multimodal-generation/generation
```

网关会按照百炼协议和“同步多模态语音识别”能力选择上游路由，并保持百炼原生的请求与响应格式。音频费用根据上游返回的有效时长按秒计算。

调试台（Playground）和模拟器（Simulator）已经增加对应的请求模板与校验。升级后可以直接在管理后台验证同步多模态语音识别，也可以继续测试已有的文件语音识别、语音合成和实时音频能力。

## 04｜用户与请求日志更容易读懂

管理后台也在本次更新中减少了日常查询和排查所需的信息跳转：

- **用户列表**：通过进度条展示已消费金额和预算上限，同时显示预算重置时间、密钥状态和专属模型价格摘要。
- **请求日志**：在同一行展示客户端入口、实际上游、供应商和路由组，并用标签标明大语言模型、流式输出、推理等请求特征。
- **调试工具**：提供更完整的请求内容预览，并补齐同步多模态语音识别和实时音频的模板校验。
- **供应商目录**：新增超算互联网 SCNet 模板，可接入 OpenAI 对话和 Anthropic Messages 接口。
- **模型预设**：阿里云百炼目录新增 `qwen-image-3.0`、`qwen-image-3.0-pro`、`wan2.7-image` 与 `wan2.7-image-pro`，均按生成图片张数计费。

![OctaFuse 请求日志并列展示入站与上游路由、功能标签、用量和三账本成本](/screenshots/v2-7-0-request-logs-redacted.webp)

*新版请求日志把客户端入口、实际上游、模型、路由组、供应商、请求特征、用量、用户计费、供应成本和利润集中在同一行，便于快速核对一次请求的完整路径和费用；截图中的用户及外部系统信息已遮蔽。*

需要注意的是，这批阿里云图片模型仍使用百炼原生接口。导入模型目录后，并不会自动支持 OpenAI 图片生成接口 `/v1/images/generations`；配置路由时仍需选择模型实际支持的上游协议。

## 升级到 2.7.0

本版本包含数据库迁移 **0026**，会为用户增加“专属模型价格”配置。D1、Postgres 和 MySQL 均已支持；没有设置用户模型倍率时，升级前后的计费结果保持不变。

升级时，请拉取同为 2.7.0 的网关代理（Proxy）、管理后台（Admin）和迁移工具（migrate）镜像。先按现有流程执行一次数据库迁移任务，再依次重启网关代理和管理后台。不要跳过数据库迁移。

升级前可查看 [GitHub Release v2.7.0](https://github.com/OctaFuse/octafuse-gateway/releases/tag/v2.7.0) 与[完整更新记录](https://github.com/OctaFuse/octafuse-gateway/blob/v2.7.0/CHANGELOG.md)。

升级后建议重点检查：

- 数据库迁移 0026 已成功完成，用户详情中的模型倍率可以正常保存。
- DeepSeek 路由的业务时区为 `Asia/Shanghai`，工作日高峰和周末全天低谷价格符合预期。
- 请求日志显示的用户倍率、命中星期、计价时段和最终费用能够相互对应。
- 通过调试台或模拟器验证百炼同步多模态语音识别，并确认原有的对话、Messages、Gemini、图片、音频和 Responses 接口仍可正常使用。

## 小结

2.7.0 让价格配置更贴近真实业务：供应商价格可以随星期和时段变化，同一模型也可以针对不同用户提供不同折扣或加价。DeepSeek 周末全天低谷计价就是最直观的使用场景。

同时，百炼同步多模态语音识别和更清晰的请求日志，也让语音能力接入、费用核对和问题排查更加方便。
