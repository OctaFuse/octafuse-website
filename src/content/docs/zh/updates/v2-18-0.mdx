OctaFuse Gateway 2.18.0 重点改进了 MCP 客户端接入和供应商粘性绑定管理。

配合已完成对接的 OAuth 授权服务器，用户可以在支持 OAuth 的 MCP 客户端中登录并授权，无需手动填写 API Key。管理员可以按用户或应用查看、撤销授权，并从请求日志追踪调用来源。

路由后台现在可以直接查看供应商的绑定分布和用户明细，支持调整绑定有效期、逐条解绑或批量清除。流式请求也改进了超时判断，避免上游持续发送心跳却没有实际内容时长时间等待。

## 01｜MCP 接入：登录授权，按应用管理访问

将 MCP 服务接入外部 Agent 时，现在可以通过 OAuth 完成登录授权。用户在客户端发起连接后，前往业务账户系统登录并同意授权，再由客户端使用独立的访问令牌调用 MCP 服务。

这些令牌与用户的 API Key 分开管理：只允许访问 MCP，不能用于聊天、模型列表等其他接口；调用费用计入令牌所属的网关用户。管理员可以在「OAuth 访问令牌」中按应用或用户查看、撤销授权，用户详情页也能查看对应记录。请求日志会标明调用来自哪个 OAuth 应用，便于追踪用量和排查问题。

### 如何启用

入口在 **MCP 服务 → 客户端接入与授权**。打开「OAuth 2.0 授权登录（可选）」，填写授权服务器地址并保存。地址须使用 HTTPS，本机开发允许 HTTP localhost。同一页的「接入指南」提供 API Key 和 OAuth 两种方式，以及 ChatGPT 连接器、Cursor、VS Code、Claude Code 和 Codex 的接入步骤。

**启用前，需要准备已与网关完成对接的 OAuth 授权服务器。** OctaFuse Gateway 负责 MCP 服务访问与令牌校验，不提供登录和授权服务器。业务账户系统需要通过网关的 Admin API 签发、轮换访问令牌，不能仅填写一个登录页地址。对接边界见 [MCP OAuth 架构说明](https://github.com/OctaFuse/octafuse-gateway/blob/v2.18.0/docs/developers/architecture/mcp-gateway.md#oauth-授权发现)。

![MCP 客户端接入与授权设置](/screenshots/v2-18-0-mcp-oauth.webp)

*在 MCP 服务页配置授权服务器，向客户端提供 OAuth 接入指引。*

访问令牌默认 1 小时有效。过期后，客户端可通过授权服务器刷新令牌；是否需要重新登录，取决于客户端和授权服务器的处理。关闭上述设置会关闭 OAuth 授权发现；如需使已签发的令牌失效，应在「OAuth 访问令牌」中撤销。

## 02｜供应商粘性绑定：看清分布，直接调整

供应商粘性让同一用户在同一模型、路由组和协议下，优先复用上次成功的供应商，有助于保持缓存连续性。这一版补上了绑定的可视化管理：从路由页打开「Provider 粘性」，即可查看分布、定位用户并处理绑定。

### 调整绑定有效期

在「配置」中启用粘性，并选择 1 小时（默认）、2 小时、6 小时或自定义有效期。设置以路由池为单位生效，覆盖该池关联的所有入口。

![Provider 粘性的开关与有效期配置](/screenshots/v2-18-0-sticky-config.webp)

*按路由池配置粘性开关和绑定有效期。*

### 查看供应商分布

「分布」按优先级展示各供应商的权重、有效绑定数和全池占比，方便确认用户当前分配在哪些供应商上。点击绑定数，可以直接进入该供应商的绑定明细。

![按供应商展示的粘性绑定分布](/screenshots/v2-18-0-sticky-distribution.webp)

*查看各供应商的绑定数与占比，并跳转到对应明细。绑定数代表绑定记录数，不等于请求量或独立用户数。*

### 定位用户并解绑

「明细」展示用户、供应商和剩余有效时间，支持按供应商筛选，以及按邮箱或用户 ID 精确查询。需要让某个用户重新选路时，可以直接解绑对应记录；需要整体重新分配时，可以在「其他」中批量清除本路由池的有效绑定。

![可按供应商或用户查询并逐条解绑的绑定明细](/screenshots/v2-18-0-sticky-bindings.webp)

*从绑定明细定位用户，查看剩余有效时间并手动解绑。*

解绑后，用户的下一次请求会按现有路由策略重新选择供应商，仍可能选回原来的供应商。批量清除也不会修改粘性开关或有效期配置。

## 03｜流式请求：心跳不再延长内容等待

部分上游会持续发送 SSE 注释心跳，却迟迟没有实际内容。现在，首包、空闲和首事件超时只认可带内容的 SSE 事件，注释心跳与空行不再延长等待。

默认情况下，等待首个有效事件超过 60 秒，且仍有未熔断的候选上游时，网关会尝试下一个候选。最后一个可用候选由首包超时兜底，保留更长的等待机会。等待响应头也有独立的超时处理，避免请求一直停留在没有响应的上游。

故障转移日志同时补充了候选上游、失败原因和熔断状态等信息，便于判断请求在哪一步失败、是否继续尝试了其他上游。

## 04｜请求详情可视化

请求日志详情改为「请求入站 → 路由与转换 → 上游尝试 → 响应结果 → 用量与记账」的流程展示，并用时间线呈现各次上游尝试及故障转移。点击阶段或某次尝试，可查看请求参数变化、上游状态、失败原因和记账信息，排障时更容易定位问题。

**改造前**，请求信息、耗时和原始数据平铺展示，追踪故障转移需要在 JSON 中查找各次尝试。

[![改造前的请求详情，耗时、定价审计和请求体等数据平铺展示](/screenshots/v2-18-0-request-detail-before.png)](/screenshots/v2-18-0-request-detail-before.png)

*改造前：数据分散在多个面板，请求经过了哪些步骤不够直观。*

**改造后**，请求流程、耗时分布和记账摘要集中展示。发生故障转移时，还能直接看到哪次尝试失败、何时切换，以及后续上游的处理结果，再按需展开对应阶段的详情。

[![改造后的请求详情，以流程卡片和时间线展示第一次上游尝试返回 HTTP 429、第二次尝试成功的过程](/screenshots/v2-18-0-request-detail-failover.png)](/screenshots/v2-18-0-request-detail-failover.png)

*改造后：从请求入站到用量与记账一目了然。时间线展示第一次尝试返回 429 后，网关切换到另一个上游并成功的过程。点击图片可查看原图。*

## 05｜其他更新

- **Gemini 签名兼容**：Gemini 原生入口遇到历史思考签名无效的特定 400 错误时，会清洗可处理的签名，并向同一上游重试一次。
- **MCP 调用校验**：拒绝 JSON-RPC 批量数组请求，避免绕过按次限流。上游返回空响应或不符合 MCP 结构的工具结果时，按失败处理且不扣费；补充资源模板列表查询，当前返回空列表。
- **路由列表布局**：按可用宽度调整分区，分开展示状态、权重、粘性和参数，方便查看配置。
- **模型与供应商目录**：新增以下预设，导入后仍需配置对应供应商和路由。

| 新增预设 | 说明 |
|---|---|
| **GPT-6.1 Terra** | 新增 `gpt-6.1-terra` 模型预设，包含短、长上下文及缓存计费配置。人民币价格为美元刊例价 ×7 的占位值，使用前请核对实际价格。 |
| **百度云模型服务 V2** | 新增广州、新加坡、加利福尼亚和法兰克福四个地域模板，与百度千帆分开。广州支持对话，其余三地另含图片及 Gemini 文本、生图；不含向量、音频和视频。各地域 Key 不能混用。 |

## 升级须知

**从 2.17.0 升级到 2.18.0，需先执行数据库迁移 0034 和 0035，再更新服务。** 从更早版本升级时，应按编号执行全部尚未应用的迁移。

1. 备份数据库。
2. 使用 v2.18.0 的 migrate 镜像应用待执行迁移；手动执行时，先执行 0034，再执行 0035。
3. 滚动更新同版本的 Proxy 和 Admin。

0034 支持粘性绑定的用户明细，0035 支持独立的 OAuth 访问令牌及请求日志关联。缺少 0034 会导致新版粘性绑定写入失败，缺少 0035 会导致新版请求日志写入失败。D1、Postgres 和 MySQL 均需执行对应迁移，具体操作见 [0034 迁移说明](https://github.com/OctaFuse/octafuse-gateway/blob/v2.18.0/docs/operators/migrations/0034-sticky-binding-affinity-key.md) 和 [0035 迁移说明](https://github.com/OctaFuse/octafuse-gateway/blob/v2.18.0/docs/operators/migrations/0035-oauth-access-tokens.md)。

升级时还需留意：

- **现有 MCP 接入**：API Key 方式继续可用，OAuth 按需配置。使用 JSON-RPC 批量数组的客户端需要改为逐条发送请求。
- **流式超时范围**：`STREAM_FIRST_EVENT_TIMEOUT_ROUTE_GROUPS` 为空时，首事件超时作用于全部路由组。此前仅在 `default` 组灰度的部署需留意范围扩大；将 `STREAM_FIRST_EVENT_TIMEOUT_MS` 设为 `0` 可关闭首事件超时。
- **已有绑定**：有效的粘性绑定继续使用。用户信息在后续成功调用续期时补全，之前显示为「未记录用户」，无需手动回填。
- **已有配置**：目录更新不会覆盖已经导入的模型价格和供应商配置，新预设需手动导入。

完整变更见 [GitHub Release v2.18.0](https://github.com/OctaFuse/octafuse-gateway/releases/tag/v2.18.0) 和 [更新记录](https://github.com/OctaFuse/octafuse-gateway/blob/v2.18.0/CHANGELOG.md)。
