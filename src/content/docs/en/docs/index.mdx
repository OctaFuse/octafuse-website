## The shortest configuration path

**Provider → model → route → user and key → real request**.

Use Playground to verify the upstream, then Simulator to check authentication, routing, charging and logs together. Images, audio, embeddings and tools are optional additions to a text-only setup.

![Request flow with routing, upstream attempts, response and accounting](/screenshots/v2-18-0-request-detail-failover.png)

Investigate failures or delays using the [request flow and timeline](/en/docs/guides/request-logs/), then use [usage and reliability](/en/docs/guides/analytics/) to decide whether routing changes are needed.

## Three different catalogs

- The [website import catalog](/en/catalog/models/) contains static presets from a released version, without your credentials or deployment configuration.
- Your gateway's public `GET /catalog/models` discovers capabilities with active routes.
- Your gateway's authenticated `GET /v1/models` is for clients, supports type filters and uses a user key.

Read [Updates](/en/updates/) for release history and these guides for current tasks.
