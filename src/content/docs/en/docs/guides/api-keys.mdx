Create calling credentials under **API Keys**. Clients send `Authorization: Bearer sk-…` to Proxy. Provider credentials stay on the gateway; Admin APIs use separate named integration keys.

## Issue and revoke keys

1. Search for an existing user, enter a user ID by hand, or resolve one using external identity.
2. Choose a recognizable key name. Save the full key according to the creation dialog; keys appear masked in the list by default.
3. Call authenticated `GET /v1/me` to verify the user and quota.
4. Issue separate keys per application; disable, revoke or delete unused credentials.

## Two RPM limits

Configure requests per minute for a user and for an individual key. Both layers must allow the request; extra keys do not bypass the user limit. Quota exhaustion and rate limiting require different responses: inspect the quota pools for the former and reduce request frequency for the latter.

Model listing and user quota queries do not consume key/user RPM and can support read-only diagnostics. See the [user API](https://github.com/OctaFuse/octafuse-gateway/blob/v2.19.0/docs/developers/api/user.md) for endpoint-specific counting.

## Four credential types

| Credential | Purpose |
|---|---|
| Provider credential | Gateway calls to the upstream provider |
| User `sk-…` key | Client requests to Proxy, charged to the user |
| MCP `oat_…` token | OAuth access to MCP endpoints only |
| Admin integration key | Trusted server calls to scoped management APIs |
