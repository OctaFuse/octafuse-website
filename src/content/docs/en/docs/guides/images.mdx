Choose the client interface first, then a compatible adapter. **OpenAI Images is a client protocol; the actual upstream may use a different native protocol.**

## Choose a path

| Path | Configuration | Important limits |
|---|---|---|
| OpenAI-compatible generation / editing | Matching OpenAI surface and upstream endpoint | Check generation and multipart edits separately |
| OpenAI interface to a native image API | A DashScope, MiniMax, Volcengine / BytePlus or Gemini image adapter | Only declared operations and mappings; generation support does not imply edits support |
| Provider-native interface | Supported native protocol with passthrough | Request, response and streaming follow that protocol |

## Configure it

1. Set the actual native or compatible provider endpoints and credentials. Use individual endpoints for partial support rather than deriving unsupported interfaces from a Base URL.
2. Import an image model and check output modalities and `image_billing_mode`. `token` uses reported usage; `per_image` uses returned images and configured price bands.
3. Select an adapter under Routes and review the client surface, upstream operation, model name and parameter mappings.
4. Probe the upstream in Playground, then verify the real Proxy request and charge in Simulator.

## Minimal client request

```bash
curl -sS http://localhost:8787/v1/images/generations \
  -H 'Authorization: Bearer sk-your-api-key' \
  -H 'Content-Type: application/json' \
  -d '{"model":"your-image-model","prompt":"a watercolor lighthouse","n":1}'
```

List image models using `GET /v1/models?kind=image`. `/v1/images/edits` is usable only when both the upstream and adapter support it. JSON reference-image generation is different from multipart editing.

**GPT Image 2.6** (`gpt-image-2.6-flare`, `gpt-image-2.6-sunburst`) supports only Images API generations and edits and cannot be the primary model for Chat Completions or Responses. `complexity` is forwarded as a client extra field; do not set it as a route default. The `svg` / `gif` output formats and the GIF `frame_count` and `frame_duration_ms` fields are likewise forwarded as extra fields and apply only to generations. Edits do not support these formats, and a markup file in an edit is currently not forwarded.

## Verify results and charges

Check returned images, image count, usage and the request's price snapshot. Client cancellation, gateway timeout, explicit upstream errors and empty results are not charged to the user. Image output does not imply per-image billing for every model.

See the [image reference](https://github.com/OctaFuse/octafuse-gateway/blob/v2.19.0/docs/developers/reference/image-models.md) and [provider coverage matrix](https://github.com/OctaFuse/octafuse-gateway/blob/v2.19.0/docs/developers/reference/native-provider-coverage.md) for sizes, parameters and native interfaces.
