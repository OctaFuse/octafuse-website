**Request Logs**, in the Logs group of the sidebar, records real Proxy calls: model requests, REST tool calls and MCP tool calls (the former Invocations page is merged here). Direct Playground probes do not generate user request records; Simulator and real clients do.

## Filter by type, model and provider

Type, Model and Provider are two-level multi-select filters, and selections are combined:

- **Type** splits into models (LLM, image, ASR, TTS, embeddings) and tools (each REST tool and each MCP server), so you can, for example, view image requests together with one tool's calls.
- **Model** is grouped by vendor and **Provider** by kind. Select a whole group or individual items, and search inside the panel.
- Multiple selections are listed below the filter bar and can be removed one by one. Filters are linked: when the scope contains only tool calls, model, provider, protocol and route-group filters do not apply.

## Start with a failed request

1. Search by the returned request ID or filter by time, user, model, provider, route group and status.
2. Compare the client interface with the actual upstream. The final provider may not be the only attempted provider.
3. Expand the request flow: Entry → Routing and conversion → Upstream attempts → Response → Usage and accounting.
4. Select a stage or attempt to inspect parameter changes, HTTP status, failure type, route information and raw snapshots.

[![Request timeline showing a 429 followed by successful failover](/screenshots/v2-18-0-request-detail-failover.png)](/screenshots/v2-18-0-request-detail-failover.png)

The timeline uses recorded attempts and waiting intervals. Missing duration is not zero duration. Upstream attempt timing and the full streaming output interval are different measurements.

Common filters expand with the page width, and conditions such as exact IDs open on demand. Time ranges use the business timezone and may be open-ended on either side or unlimited. Amounts in the list keep the billing and cost multipliers beside them. When an upstream returns an HTML error page, the list shows a summary and the full body stays in the request detail. To watch new traffic, turn on auto refresh (10 seconds to 5 minutes); while you read the list, new entries are announced before they appear.

## Tool call details

Tool call details show an overview, request, response and accounting instead of the model request flow. REST tools list the engine, request parameters and results; MCP tools list the server, upstream tool, arguments and returned content. Switch the request and response areas between Preview and Raw data at the top right. When a call fails, the top of the detail shows the original error and what to check, with links to the tool configuration or MCP server.

## Check charges

Usage and accounting separates the user charge, supplier cost and recorded price snapshot. Review official schedules, Provider factors, route windows and model/group discounts. Do not recompute an old bill from today's configuration.

Use [Audit Logs](/en/docs/guides/audit-logs/) for changes to the budget and wallet pools. Currency and business timezone determine amount and business-day interpretation.

## MCP and sticky routing

Filter MCP calls by service; OAuth calls identify the application and charge its associated user. For Sticky, combine lookup, unbind and rebound information with cache-read usage and failover counts.

One request explains one execution. Use [usage and reliability](/en/docs/guides/analytics/) for trends. See the [log API reference](https://github.com/OctaFuse/octafuse-gateway/blob/v2.21.0/docs/developers/api/admin.md) for fields.
