**Request Logs** records real Proxy calls. Direct Playground probes do not generate user request records; Simulator and real clients do.

## Start with a failed request

1. Search by the returned request ID or filter by time, user, model, provider, route group and status.
2. Compare the client interface with the actual upstream. The final provider may not be the only attempted provider.
3. Expand the request flow: Entry → Routing and conversion → Upstream attempts → Response → Usage and accounting.
4. Select a stage or attempt to inspect parameter changes, HTTP status, failure type, route information and raw snapshots.

[![Request timeline showing a 429 followed by successful failover](/screenshots/v2-18-0-request-detail-failover.png)](/screenshots/v2-18-0-request-detail-failover.png)

The timeline uses recorded attempts and waiting intervals. Missing duration is not zero duration. Upstream attempt timing and the full streaming output interval are different measurements.

Common filters sit on top and advanced conditions below. Time ranges use the business timezone and may be open-ended on either side or unlimited. Amounts in the list keep the billing and cost multipliers beside them. When an upstream returns an HTML error page, the list shows a summary and the full body stays in the request detail.

## Check charges

Usage and accounting separates the user charge, supplier cost and recorded price snapshot. Review official schedules, Provider factors, route windows and model/group discounts. Do not recompute an old bill from today's configuration.

Use [Audit Logs](/en/docs/guides/audit-logs/) for changes to the budget and wallet pools. Currency and business timezone determine amount and business-day interpretation.

## MCP and sticky routing

Filter MCP calls by service; OAuth calls identify the application and charge its associated user. For Sticky, combine lookup, unbind and rebound information with cache-read usage and failover counts.

One request explains one execution. Use [usage and reliability](/en/docs/guides/analytics/) for trends. See the [log API reference](https://github.com/OctaFuse/octafuse-gateway/blob/v2.19.0/docs/developers/api/admin.md) for fields.
