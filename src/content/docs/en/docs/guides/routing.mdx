A call matches a **Request Surface**, enters a **Route Pool**, then tries an **Upstream Target**. The model ID, route group, protocol and operation determine the surface.

## Create a route

1. Prepare a provider and model, then select a compatible protocol adapter.
2. Review the client protocol and operation: Chat, Responses, Messages, image, audio or embedding.
3. Select a pool and group, enter upstream model and provider, choose priority and weight, then enable and save.
4. Probe the target in Playground and verify the full client-to-accounting path in Simulator.

An OpenAI image surface may use a supported native upstream adapter. Conversion is limited to implemented combinations; see [capability limits](/en/docs/capabilities/).

## Priority and four strategies

Higher `priority` is attempted first. Within one tier:

| Strategy | Use |
|---|---|
| `hash_affinity` (default) | Stable preference by user, model, group and protocol for cache continuity |
| `weighted_random` | Random selection proportional to weight |
| `weight_priority` | Fixed descending weight order within the tier |
| `weighted_round_robin` | Weighted rotation; counters are not shared between runtime instances |

A tier may override the strategy. Otherwise pool, model and global rules are inherited. See the [strategy reference](https://github.com/OctaFuse/octafuse-gateway/blob/v2.18.0/docs/developers/reference/route-strategies.md) for exact precedence.

## Provider Sticky

Sticky routing remembers the last successful target for a configured lifetime. It is independent of tier strategies and disabled by default. Open Provider Sticky to set the lifetime, inspect distribution and user bindings, unbind one record or clear the pool.

![Sticky binding details and unbind controls](/screenshots/v2-18-0-sticky-bindings.webp)

Unbinding re-runs selection and may still choose the same target. Bindings are persisted across instances, whereas `hash_affinity` is a stateless hash.

## Custom headers and body

Headers and JSON body have separate configuration. Explicit client values win by default. Each side has its own Force override switch, making route values take precedence on that side only. Do not place HTTP headers inside the JSON request body.

![Independent header and body force override](/screenshots/v2-10-0-route-force-override.webp)

## Prices and validity windows

Maintain Provider, Charged and Metered factors separately. Provider factors may have validity windows. Official model schedules and route schedules have different roles; inspect the complete price preview before saving. See [pricing and discounts](/en/docs/guides/billing/) for user factor composition.

## Failures and streaming

Retryable supplier failures allow subsequent candidates; circuit breakers avoid repeatedly calling unavailable accounts. Streaming first-event detection ignores comment heartbeats. The default first-event timeout is 60 seconds; another usable candidate permits failover, while the last candidate falls back to the first-chunk timeout.

Inspect actual attempts in the [request timeline](/en/docs/guides/request-logs/). See the [request lifecycle](https://github.com/OctaFuse/octafuse-gateway/blob/v2.18.0/docs/developers/architecture/proxy-request-lifecycle.md) for precise timeout and retry conditions.
