Separate two paths: applications call **Proxy** with user credentials; a trusted business backend calls **Admin APIs** with named integration keys to maintain users, keys, quotas and configuration.

## URLs and credentials

| Conventional variable | Purpose |
|---|---|
| `GATEWAY_URL` | Proxy root URL for model and tool requests |
| `GATEWAY_MASTER_URL` | Admin root URL, with management calls under `/api/admin/*` |
| `GATEWAY_MASTER_KEY` | A named Admin integration key; the historical variable name does not require the old shared Master Key |

Create least-privilege keys under **System → Integration Keys** for each business system. Keep them on trusted servers, not in browser apps or ordinary inference SDK credentials.

## Typical provisioning flow

1. Resolve a gateway user idempotently from external system and user identifiers after business signup.
2. Set a periodic plan or add permanent wallet credit, using a unique reference for each credit operation.
3. Issue a user key and deliver it according to your trust boundary, or retain it server-side.
4. Send application calls to Proxy; read usage and audit through management interfaces.
5. Configure optional model/group discounts consistently with the global factor composition mode.

See [Models](/en/docs/guides/models/) for the distinction between public discovery, user model lists and website presets. MCP sign-in requires an additional [authorization-server integration](/en/docs/guides/oauth/).

## Existing integrations

After confirming named integration keys have replaced `legacy-master`, rotate or revoke the legacy key under your migration plan. Use wallet credit for purchases rather than incrementing a periodic budget cap.

See the [integration reference](https://github.com/OctaFuse/octafuse-gateway/blob/v2.19.0/docs/developers/integration.md) and [Admin API](https://github.com/OctaFuse/octafuse-gateway/blob/v2.19.0/docs/developers/api/admin.md) for fields and idempotency.
