Create gateway accounts under **Users**. The user owns quotas, charging and user-level rate limits; API keys belong to that user. Multiple keys share the user's quota rather than creating additional allowance.

## Create and maintain an account

1. Create a user for a member, project or customer. Set email and status; use external system and user identifiers for a product integration.
2. Configure periodic budgets, reset periods and wallet credit under Quotas and billing. Read [pricing and quotas](/en/docs/guides/billing/) for their behavior.
3. Set optional model or route-group factors. After saving, use the model list preview to check the user's model and discount view.
4. Issue and manage [API keys](/en/docs/guides/api-keys/) for the user.
5. Follow activity, request logs and audit logs to investigate usage and quota changes.

The user list focuses on identity, status, quota and configuration; the full user ID is in the details. The form expands optional fields on demand and validates email, identity, quota and JSON, and the details link to the user's keys and usage records.

## Maintain the quota pools separately

Plan budgets and permanent top-up credit serve different purposes. Use the wallet credit API with a unique business reference for purchases, so an order retry does not duplicate credit. Editing the periodic cap is not a top-up operation.

User forms edit configuration. Use current accounting records for consumed amounts; changing a budget period does not imply erasing consumption.

## Keys and OAuth applications

One user can have several API keys. MCP OAuth applications use separate access tokens, while charges remain with the user. View and revoke those grants in the user details. Read [OAuth setup](/en/docs/guides/oauth/) for its prerequisites.
