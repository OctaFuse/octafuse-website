**Models** defines client-facing IDs, vendors, modalities and catalog pricing. Routes map these IDs to upstream model names so clients can use a stable name.

## Import and configure

1. Import from the [model catalog](/en/catalog/models/) or create a custom model.
2. Check its kind: LLM, image, ASR, TTS or embedding. Modalities and valid pricing rules determine the kind together.
3. Review context, maximum output, release date, notes and pricing. Tags are administrator-managed; import does not create routes.
4. Add a usable upstream and active surface under [Routes](/en/docs/guides/routing/), then make a real call.

## Sync with the official catalog

Manually trigger **Sync**; it compares first and applies only after you confirm. It compares names, modalities, specifications, descriptions and prices. Choose official or local values per model or in bulk. **Prices are kept by default; inspect affected routes before applying changes.** Missing official fields do not clear local values.

![Official model catalog comparison](/screenshots/v2-15-0-model-official-sync.webp)

Imported records and the website catalog are different data sets. Refreshing static presets does not silently change deployed prices, tags or routes.

## Kind and billing

| Kind | Check |
|---|---|
| LLM | Input, output and cache prices, long-context tiers and official schedules |
| Image | Token or per-image mode and size, quality or reference-image conditions |
| ASR / TTS | Duration, characters or tokens, matching the adapter's measured usage |
| Embedding | Input token price; excluded from default model listing |

## Three discovery interfaces

- Website catalog: released import presets, including models not enabled in your deployment.
- Your gateway's public `GET /catalog/models`: capabilities with active routes.
- User-authenticated `GET /v1/models`: LLMs by default, with `kind=image/asr/tts/embedding` and other filters.

See the [model-kind reference](https://github.com/OctaFuse/octafuse-gateway/blob/v2.19.0/docs/developers/reference/model-kinds.md) and [client configuration](/en/docs/guides/clients/) for IDs and route groups.
