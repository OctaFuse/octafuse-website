**REST Services** exposes independent tool APIs under `/v1/tools/*`. They are separate from model conversation protocols: the client executes these requests after a model asks to use a tool.

| Service | Endpoint | Implemented engine examples |
|---|---|---|
| Web search | `/v1/tools/web-search` | Bocha, Tavily, CleverSee, Tencent WSA |
| Web fetch | `/v1/tools/web-fetch` | Firecrawl, Tavily Extract, Jina Reader |
| Deep search | `/v1/tools/web-deep-search` | Firecrawl Search, Jina Search |
| AI detection | `/v1/tools/ai-detection` | Tencent TMS |

## Configure and activate

1. Open REST Services under Agent Tools. Filter by name, service type or status.
2. Open a service dialog to edit credentials, activation, pricing and tests.
3. Set Standard price, Charged factor and Metered factor; check the price preview. Search bills per request; AI detection uses configured character units.
4. Save and activate the intended engine. Each tool currently has one Active engine; unimplemented engines or incomplete credentials cannot be activated.
5. Call Proxy with a user key, then review tool invocations or request logs.

A zero Charged factor makes user calls free while retaining supplier cost. Model route schedules and per-model user discounts do not apply. Legacy independent unit prices remain readable; newly saved rules use a base price and factors.

## Test a search

```bash
curl -sS http://localhost:8787/v1/tools/web-search \
  -H 'Authorization: Bearer sk-your-api-key' \
  -H 'Content-Type: application/json' \
  -d '{"query":"OctaFuse gateway","count":5}'
```

Upstream failures are not charged. Calls require a usable Active engine. Read [MCP servers](/en/docs/guides/mcp/) to connect external standardized tool services; REST tools are not automatically exposed as MCP.

See the [tool API reference](https://github.com/OctaFuse/octafuse-gateway/blob/v2.18.0/docs/developers/api/user.md) for fields and engine limitations.
