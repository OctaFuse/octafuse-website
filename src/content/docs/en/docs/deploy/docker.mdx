Docker suits your own hosts, private networks and container platforms, with Postgres or MySQL. Start locally using [Quick start](/en/docs/quick-start/) or compare [deployment options](/en/docs/deploy/overview/).

## Choose a template

| Need | Repository template |
|---|---|
| Complete local evaluation | `docker/compose/quickstart.yml` |
| Self-hosted Postgres | `docker/compose/node-pg.yml` |
| Self-hosted MySQL | `docker/compose/node-mysql.yml` |
| External database with prebuilt images | `docker/examples/` |

Use matching Proxy, Admin and migrate image versions. Pin production tags or digests. Supply database credentials through environment or secret configuration and point all three processes at the same database. MySQL needs its explicit driver selection.

## First deployment

1. Prepare the database, persistence, backups and template environment values.
2. Run the one-shot migration job and confirm success.
3. Start Proxy and Admin, then configure providers, models and routes.
4. Set production Admin credentials and named integration keys, and serve through HTTPS.

The local `admin / changeme` account is an example only. Keep database credentials, Admin passwords and upstream keys out of version control.

## Verify

Check Proxy `/health`, sign in to Admin and send a real request with a dedicated test user. Verify logs, usage and quota changes. Test WebSocket operations separately when using realtime audio.

A running container and passing health check do not mean a model or tool is configured.

## Upgrade

Read [upgrade notes](/en/docs/deploy/upgrades/), back up and plan a maintenance window. Apply pending migrations, then roll the same service version. Enable automatic migration on one deliberately chosen side rather than making several processes responsible for it.

See the [Docker reference](https://github.com/OctaFuse/octafuse-gateway/blob/v2.19.0/docs/operators/deployment/docker.md) for Compose commands, image names, environment variables and hosting differences.
