In this deployment Proxy and Admin each run as a Worker and share D1. Cloudflare is one supported option; resource limits and charges depend on the plan and actual usage.

## Bootstrap

Prepare a Cloudflare account, Node.js and npm. In the target Gateway release checkout run:

```bash
npm install
npx wrangler login
npm run bootstrap:cloudflare
```

Follow the prompts to create or select resources and set Admin credentials. Record the resulting Proxy and Admin URLs. Use the [Cloudflare quick deployment reference](https://github.com/OctaFuse/octafuse-gateway/blob/v2.18.0/docs/operators/deployment/cloudflare-quickstart.md) for exact resource settings and troubleshooting.

## Configure and verify

1. Sign in to Admin, configure providers, models and routes, then create a test user and key.
2. Test a normal model request followed by the image, audio, embedding or MCP operations your application needs.
3. For realtime capabilities, verify native WebSocket connection and returned events.
4. Inspect request flows and account changes rather than relying on `/health` alone.

## Upgrades and migrations

Pin the target version and read [Upgrades](/en/docs/deploy/upgrades/). Back up D1, apply all pending release migrations, then deploy matching Proxy and Admin versions. Follow an existing Workers Builds or Git integration flow rather than accidentally deploying duplicate resources.

Store credentials as platform secrets or protected deployment values. Use the [deployment overview](/en/docs/deploy/overview/) and database cutover reference before changing to Postgres or MySQL.

See the [Cloudflare operations reference](https://github.com/OctaFuse/octafuse-gateway/blob/v2.18.0/docs/operators/deployment/cloudflare.md) for build and configuration details.
