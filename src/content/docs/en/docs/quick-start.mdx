The goal is a complete **client → gateway → upstream → logs and charging** request. Pick a runtime, then follow the same configuration steps.

## 1. Start the gateway

### Local Docker setup

Install Docker and Compose, then clone the released version:

```bash
git clone --branch v2.19.0 --depth 1 https://github.com/OctaFuse/octafuse-gateway.git
cd octafuse-gateway
docker compose -f docker/compose/quickstart.yml up --build
```

This example starts Postgres, a migration job, Proxy and Admin. Proxy listens on `http://localhost:8787`, Admin on `http://localhost:8789`; local example credentials are `admin / changeme`.

### Cloudflare local setup and deployment

Install Node.js and npm. In the same repository run:

```bash
npm install
npm run db:migrate
npm run dev:proxy
```

Run `npm run dev:admin` in another terminal. Proxy and Admin use `127.0.0.1:8787` and `127.0.0.1:8789`; local credentials are `admin / admin`. See [Cloudflare deployment](/en/docs/deploy/cloudflare/) to deploy to your account.

These credentials are for local examples. See [deployment options](/en/docs/deploy/overview/) for production passwords and data placement.

## 2. Configure one model

1. Import a Provider you use, supply its upstream credential and check its protocol endpoints.
2. Import a model the account can call. This creates a model record, not a route.
3. Add an upstream target under Routes, choose a compatible adapter and enter the upstream model name. Keep route group `default` initially.
4. Test that target in Playground to verify credentials, endpoint and model access.
5. Create a user with a [periodic budget or wallet credit](/en/docs/guides/billing/), then create a user API key.

## 3. Send a real request

```bash
curl -sS http://localhost:8787/v1/chat/completions \
  -H 'Authorization: Bearer sk-your-api-key' \
  -H 'Content-Type: application/json' \
  -d '{"model":"your-route-model","messages":[{"role":"user","content":"Hello"}]}'
```

Replace the model and key. Use your Proxy address after deployment. Chat requires an active Chat surface; Responses and other protocols need their own surfaces and request formats.

## 4. Verify the full path

- Check the returned model content.
- Open [request logs](/en/docs/guides/request-logs/) to inspect the selected provider, attempts, usage and accounting.
- Call authenticated `GET /v1/me` to check the periodic budget, wallet balance and total remaining quota.

Playground's direct probes do not create these user request records. [Simulator](/en/docs/features/simulator/) can perform the same full-path checks.
