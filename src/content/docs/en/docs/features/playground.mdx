**Playground** checks whether one upstream works. It does not use the user charging path, consume user quota, write user request logs or exercise full routing and failover. The upstream itself may still charge for probes.

## Workflow

1. Select an upstream route and check protocol, operation and upstream model name.
2. Load a Chat, Responses, image, audio or embedding example; edit the body and headers needed.
3. Send and inspect status, response, streaming events or multimodal output.
4. Re-test after changing configuration; do not rely on a result from an older draft.
5. Use [Simulator](/en/docs/features/simulator/) for real user authentication, routing, charging and logs.

![Embedding probe example](/screenshots/v2-15-0-embedding-playground.webp)

The route editor can also probe unsaved target configuration; testing does not save it. Tools mode calls configured REST engines directly. Follow the [MCP guide](/en/docs/guides/mcp/) for MCP catalog and real tool-call checks.

## Realtime audio

Supported realtime recognition routes can use the browser microphone. Check browser permission and the model's native WebSocket operation. Audio models do not all share one realtime interface.
