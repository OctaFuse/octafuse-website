**Simulator** sends real requests from your browser to Proxy. Use a test user's key to verify authentication, routes, quotas, failover and accounting together.

## Verification steps

1. Enter the Proxy root URL and a valid user API key.
2. Select the client model, route group and surface. Supported categories include chat, images, audio, embeddings and REST tools.
3. Edit a request for that protocol and send it.
4. Find it in [request logs](/en/docs/guides/request-logs/) and inspect attempts, usage and accounting.
5. Reconcile quota deductions with user and audit records.

![Client model and request surface selection](/screenshots/v2-6-0-simulator-routing-target.webp)

While a request is in flight the Simulator locks its connection and target. The request still produces real charges and logs.

Simulator constructs the **client-side** request. It does not send the final upstream protocol directly. For example, the gateway converts OpenAI Images to a Gemini upstream when configured with that adapter.

## When Playground succeeds but Simulator fails

Check user and key status, quota, RPM, model ID, route group and active surfaces. Playground success only confirms the individual upstream, not every user-side condition.

The key is used in your browser. Use a trusted environment and dedicated test credentials, and clear saved state on shared devices. For MCP clients, follow the [MCP guide](/en/docs/guides/mcp/).
